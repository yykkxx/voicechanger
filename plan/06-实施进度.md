## 2.6.1 会话 #4 追加修复：点击"开始变声"闪退（立体声展开越界）

**用户反馈**：点击"开始变声"立即闪退。

**崩溃日志（logcat -b crash / dropbox）**：
```
java.lang.ArrayIndexOutOfBoundsException: length=480; index=959
	at com.voicechanger.app.audio.PolicyTrackInjector.write(PolicyTrackInjector.kt:45)
	at com.voicechanger.app.audio.AudioPipeline.injectLoop(AudioPipeline.kt:147)
```

**根因**：`PolicyTrackInjector.write` / `InjectionEndpoint.write` 在 `stereoExpansion=true`
时做 mono→stereo 展开，但**原地写回原数组**（`frame[i*2]=frame[i]`），而帧数组长度只有
480（10ms@48k mono），展开需要 960 容量 → 越界崩溃。默认后端
`policy_recorder_mix` 使用 `stereoExpansion=true`，所以一键必崩。

**修复**：
- 两个 Injector 均增加翻倍容量 `stereoBuf`，先展开到独立缓冲再 `track.write`；
- `writeSilence` 显式清零缓冲（避免复用残留人声数据）；
- 保持实时线程零分配（缓冲在构造时分配一次）。

**验证**（系统命令触发 `ACTION_START`，未操作 UI）：
```
VC/PolicyMix: policy registered; matched=capture_preset(VOICE_COMMUNICATION)
VC/Capture: AudioRecord opened
VC/Pipeline: pipeline started
VC/Service: session running: mode=INTERNAL backend=policy_recorder_mix
```
- 变声会话正常启动、运行，无 FATAL / ArrayIndexOutOfBounds；STOP 后进程正常驻留。
- 版本 v1.1 (versionCode 2)；模块与即时安装均已同步修复版。

## 2.6.2 会话 #5 追加：路由问题定位与修复（全局静音 / 返听无声 / 录音无效果）

> 详见 [09-真机路由问题定位与修复.md](./09-真机路由问题定位与修复.md)。

**用户反馈**（OnePlus PJZ110 / ColorOS 16）：
1. 任意模式、耳机、返听开关 → 听不到处理后人声；
2. 变声开启后所有软件播放无声，关闭后恢复；
3. 变声期间录制的音频无变声效果。

**根因（多重叠加）**：
- 默认 `policy_recorder_mix` 后端误用 `ROUTE_FLAG_LOOP_BACK`(0x01)（语义=把播放流复制给自己读），
  实际需要 `ROUTE_FLAG_RENDER`(0x02)（把 track 数据渲染给录音客户端）；
- 本 ROM 上 `setMixType(int)` 反射不可用 + RENDER 缺注入设备（`IllegalArgumentException: Can't have flag ROUTE_FLAG_RENDER without an audio device`）；
- 厂商虚拟设备（`ip_out`/`ip_input_device`）配置存在但**本机未加载**（`libvirtualaudio.so` 注册 `mandatory="false"`，可用设备列表无 IP 设备）→ `getDevices()` 枚举不到；
- 因此 policy/oplus 注入后端在本机都不可用，且注册 recorder mix 参与主混音导致全局播放被静音。

**修复（已构建部署）**：
- ✅ `RouteRegistry.selectAuto`：AUTO **首选 MonitorOnlyBackend（监听/返听模式）**，不注册任何 AudioPolicy、不触碰全局路由 → **全局播放不再被静音**；
- ✅ 监听/返听统一 stereo 展开并显式绑定耳机设备 → **耳机能听到处理后人声**（主注入即返听）；
- ✅ 返听开关在 monitor 模式下不再重复开第二条轨（避免双写互抢）；
- ✅ `PolicyRecorderMixBackend` 保持 RENDER 语义 + 递归解包真实 cause（`InvocationTargetException` 定位）；
- ✅ 验证：`session running: mode=INTERNAL backend=monitor`；无 policy 注册事件；无残留 mix。

**仍未解决（Phase 1 范围，透明说明）**：
- 录音无变声效果：目标应用录音仍走物理麦克风。要让录音带变声效果，必须完成
  注入链路（Remote Submix / 厂商虚拟设备 + framework 路由到目标 UID），
  这是 Phase 1 标记音验证的内容，验证通过前不宣称支持。
- 待用户实测确认：全软件播放正常 + 耳机返听有声。
