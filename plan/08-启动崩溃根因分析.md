# 08 启动崩溃根因分析（ReSukiSU umount 与 Compose 崩溃）

> 2026-09-19 真机取证（OnePlus PJZ110 / ColorOS 16 / Android 16）。
> 本文记录**两类独立崩溃**的完整证据链与修复方向。

## 1. 崩溃 A：点击「生成能力报告 / 注册探测」闪退（已定位，代码修复）

**日志（法规时间 09:40:09，旧版本）**：

```
java.lang.IllegalStateException: Vertically scrollable component was measured with an
infinity maximum height constraints, which is disallowed...
	at androidx.compose.foundation.CheckScrollableContainerConstraintsKt...
```

**根因**：诊断页里 `Column(verticalScroll)` 内部又嵌套了一个带 `verticalScroll` 的
`Text`（诊断报告区域），嵌套滚动在测量时产生无限高度约束，Compose 直接抛异常终止进程。

**修复**（本次代码已完成）：
- 移除内层 `verticalScroll`，改为单一滚动容器；
- 诊断文本预先在按钮点击时生成（后台线程），避免在 Composable 里做耗时操作；
- 全部按钮/探测/复制操作增加 `runCatching` 包裹与日志（`VC/Diag` tag），任何异常都
  显示为页面上的错误信息而不是崩溃。

## 2. 崩溃 B：模块安装重启后，每次冷启动直接闪退（设备配置问题）

**日志链（09:54 之后每次启动必现）**：

```log
# 1) 应用进程读取自己的 APK 失败
ziparchive: Unable to open '/system/priv-app/VoiceChanger/VoiceChanger.apk': No such file or directory
kloadclassifier: Failed to open APK '/system/priv-app/VoiceChanger/VoiceChanger.apk': I/O error
ResourcesManager: failed to add asset path '/system/priv-app/VoiceChanger/VoiceChanger.apk'

# 2) 系统资源为空 → 图形环境初始化 NPE → 进程必崩
java.lang.NullPointerException: getStringArray(int) on a null object reference
	at android.os.GraphicsEnvironment.queryAngleChoice(GraphicsEnvironment.java:477)
	at android.app.ActivityThread.setupGraphicsSupport(ActivityThread.java:8258)  ← handleBindApplication 阶段
```

**关键佐证（本次新增）**：

```log
# 3) 系统在启动瞬间把模块挂载从该进程卸载了（ReSukiSU/KernelSU 内核日志）
KernelSU: ksu_handle_umount: unmounting: /system/priv-app flags 0x2

# 4) 系统中其他模块应用的进程正常（gkd/vtools 能读到自己的 APK），
#    但 bilibili 等普通进程看不到 /system/priv-app/VoiceChanger（umount 生效）
```

**结论**：设备上的 root 隐藏栈（ReSukiSU + hma_oss_zygisk + AppOpt + mountify）
在**应用进程启动时执行了 `unmount modules`**，导致应用无法读取自己的 APK 文件。
这是**设备配置问题，不是应用 bug**——同样的 APK 在任何未启用 "unmount modules for
this app" 的设备上可以正常启动。

**修复路径（按优先级，需在设备端操作）**：

1. **ReSukiSU 管理器**：找到本应用（Voice Changer / com.voicechanger.app）的
   **App Profile / 隐藏设置**，将「卸载模块（Unmount modules）」设为**关闭/不应用**。
   （对应内核开关：`ksu_handle_umount` 对该 UID 的触发）
2. 检查 **hma_oss_zygisk**、**AppOpt** 等模块是否有针对白名单/黑名单的配置，
   将 `com.voicechanger.app` 加入"不隐藏挂载"的白名单。
3. 若使用 susfs：`sus_path` 与 `hide_sus_mnts_for_non_su_procs` 配置不会导致此崩溃，
   但若 ReSukiSU 内置了 per-app umount，仍以第 1 条为准。
4. 验证命令（设备端）：

```bash
# 应用进程启动瞬间检查（应能看到 APK）：
am start -n com.voicechanger.app/.MainActivity &
grep VoiceChanger /proc/$(pidof com.voicechanger.app)/mounts
# 期望输出包含 /system/priv-app/VoiceChanger/VoiceChanger.apk

# 或对比：应用应能读到 /system/priv-app/VoiceChanger/ 目录
```

5. 短期绕行方案（不改模块配置时）：**不要勾选"对全部应用隐藏"**，
   或临时关闭对 com.voicechanger.app 的隐藏（thanox/AppOpt 里配置）。

> 备注：该问题会在**任何**通过模块挂到 priv-app、且被 root 隐藏机制
> unmount 的应用上出现（与我们的应用无关）。用户的设备同时装有 Thanox、
> hma_oss、AppOpt 等多套隐藏方案，应逐一定位具体是哪一个在 umount。
