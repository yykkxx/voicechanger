# 13-AI杂音根因修复与模型部署

## 日期
2026-09-24

## 背景
用户反馈所有 AI 变声模式（RVC、OpenVoice、FreeVC、DDSP）输出中存在大量杂音，
录音设备本身纯净无问题，确认杂音来自音频处理链。

## 根因分析

### 1. FIR 抗混叠滤波器延迟线 bug（核心问题）
所有 4 个处理器共享相同的 FIR 降采样实现，其中存在一个致命的延迟线索引错误：

```kotlin
// 旧代码（错误）：
val v = if (j < dN) firDelay[j] else x  // ← 最后一个 tap 用当前样本 x 而非 delay 线中最老样本
```

**问题**：`firDelay` 数组大小为 `DECIM_TAPS - 1`（22 个元素），延迟线右移后
`firDelay[0]` 存最新样本、`firDelay[21]` 存第 22 个历史样本。但卷积需要 23 个样本
（h[0]..h[22]），代码在 `j == 22` 时用 `x`（= `firDelay[0]`，最新样本）代替了
本应是「最老样本」的位置 → **最新样本被双重计入**（h[0]·x + h[22]·x）。

**后果**：
- 滤波器频率响应变形：通带起伏 + 阻带泄漏
- 8kHz 以上镜像频率未被充分抑制 → 折叠回 0-8kHz 带内 → **持续性金属杂音**
- 每个样本的滤波结果都不正确 → **沙沙噪声**

### 2. 滤波器阶数不足
旧 FIR 仅 23 阶（22 阶 + 1），截止频率 5.3kHz，阻带衰减约 40 dB。
对于 48k→16k 的 3:1 抽取，需要更陡峭的过渡带和更高的阻带衰减。

### 3. 缺少输出后处理
AI 模型输出常带：
- 直流偏置（DC offset）→ 低频嗡嗡声
- 静音段底噪 → 呼吸感噪声
- 帧边界高频颗粒 → 嘶嘶声

## 修复方案

### A. 新建 `Resample.kt`（高质量重采样与音频净化工具）

#### `Design.firLowpass(taps, cutoff, fs)`
- Blackman-Harris 窗函数法线性相位 FIR
- 63 阶，截止 7kHz @ 48kHz → 阻带衰减 > 90 dB
- 直流增益归一化（旧系数未归一化 → 音量偏小）

#### `FirDecimator(ratio, taps, cutoffHz, fs)`
- 延迟线 `delay[0]` = 最新样本，`delay[n-1]` = 最老样本
- 卷积 `y[n] = Σ h[k]·delay[k]`（**语义严格正确**）
- 不再有「最老样本用当前样本代替」的错误

#### `DcBlocker`
- 一阶高通：`y[n] = x[n] - x[n-1] + R·y[n-1]`，R=0.995
- 截止约 38 Hz @ 48 kHz，消除直流漂移

#### `NoiseGate`
- 软噪声门：低于 -48 dB 的帧衰减到 12% 增益
- attack=2ms / release=120ms 包络跟踪
- 平滑过渡，避免「开关门」呼吸感

#### `HighBandSmoother`
- 一阶 IIR 低通提取 6kHz 以下分量
- 高频分量衰减 30% 后叠加回原信号
- 消除帧边界高频颗粒噪声

### B. 修复全部 4 个处理器

| 处理器 | 修改内容 |
|--------|---------|
| `RvcProcessor` | 替换 FIR → FirDecimator(3,63,7k,48k)；process() 添加 DC+NG+HS 后处理 |
| `OpenVoiceProcessor` | 同上 |
| `FreeVcProcessor` | 同上 |
| `DdspProcessor` | 同上 |

- 来源：`seasonstudio/openvoice_tone_clone_onnx`（HuggingFace）

- 输入：`src_tone` [1,T,80] + `dest_tone` [1,T,80]（源/目标 mel）
- 输出：`audio` [1,1,N]（转换后波形）
